The Kafka MCP Server

A reference implementation of KIP-1318. Pure-Python, in-memory Kafka backend, and a 9-step fail-closed control pipeline that decides what an agent is allowed to do before anything touches the broker.

Scope & access

Topic/group prefix allow-lists (agent.*, sandbox.*), readonly mode, tool allow/deny lists, pluggable policy engine.

Approval gate

HMAC-signed, TTL-bounded tokens bound to tool + resource + principal, with single-use nonce replay protection.

Data protection

DLP redaction/blocking for keys, JWTs and AWS creds; payload-only scrubbing; byte-bounded reads.

Integrity & resilience

Taint/IFC so untrusted data can't drive mutate/destructive calls; rate limits, circuit breakers, anomaly tracking, audit sink.

Security model

A 9-step, fail-closed pipeline where the first denial wins, mapped to the OWASP Top 10 for LLM Applications. Identity comes only from the transport, never from tool arguments.

LLM01 Prompt Injection

Taint guard / IFC and sensitive-topic gating stop read-derived data from driving destructive calls (-32040).

LLM06 Excessive Agency

Prefix scope, allow/deny, readonly, approval tokens, dry-run, and a rogue-agent kill-switch (-32041 / -32042 / -32047).

LLM02 & LLM10

DLP redaction and config masking for disclosure; rate limits, circuit breakers, and bounded reads for unbounded consumption.

Proof: re-validation results 100% pass

Every guardrail is expressed as a test. Denials return the right error code (scope -32041, approval -32042), not just "something threw."
